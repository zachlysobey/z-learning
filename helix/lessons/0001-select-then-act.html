Select, then act

The one idea that makes every other Helix key make sense.

Mission link. You want Helix to replace VS Code for real editing. In an IDE you always see what you've selected before you hit delete. Helix works the same way, in the keyboard. This lesson installs that rhythm; multiple cursors, later, are just this idea with more than one selection.

The idea

In Helix there is always a selection. The cursor is just a one-character selection. Movement keys don't move a cursor, they move a selection. Then a single key acts on it.

So where vim says dw (verb, then object), Helix says wd: w selects up to the next word start, and you can see the highlight before d deletes it. If the selection is wrong, you notice before anything happens. (docs: Usage)

Six keys to own today

KeyWhat it doesSource
w b eSelect to next word start / previous word start / next word endkeymap: movement
xSelect the current line; press again to extend to the next linekeymap: selection
;Collapse the selection back to a single cursorsame
dDelete the selectionkeymap: changes
cChange: delete the selection and enter insert modesame
vSelect (extend) mode: movements grow the selection instead of replacing itkeymap: select mode

Translating your vim habits

You want tovimHelixRead it as
delete a worddwwdselect word, delete
change a wordcwecselect to word end, change
delete a lineddxdselect line, delete
delete 3 lines3ddxxxd or 3xdselect three lines, delete
delete to end of lineDvgldextend to line end, delete
go to line end$glgoto line-end

Full table: wiki: Migrating from Vim. Julia Evans, after 20 years of vim, says the switch took "a week or two" and advises learning the Helix way rather than remapping it to vim (her notes).

One trap: after w the selection is highlighted, and a plain i inserts before that selection, a after it. If you just want a cursor, press ; first. The selection never silently goes away.

Do it

Task 1 — the tutor, targeted (≈10 min)

  1. Run hx --tutor.
  2. Do sections 1.3 Deletion, then 3.1 through 3.4 (motions, selections, words, change), then 3.7 and 3.8 (selecting lines, collapsing). Skip the rest for now.
  3. Quit with :q!. The tutor is a scratch copy; nothing to save.

Task 2 — a real file, with a check (≈5 min)

Create the file, edit it in Helix using only the keys above, then run the check. The check prints nothing when you got it right.

cat > /tmp/hx-lesson1.txt <<'TXT'
the quickly brown fox
jumps over the lazy dog
this line should be deleted entirely
colour = blue
keep this last line
TXT
hx /tmp/hx-lesson1.txt

Make these four edits, in order:

  1. Line 1: delete the word quickly (with its trailing space) → the brown fox. Hint: put the cursor on the q, then wd.
  2. Line 2: change lazy to sleepy. Hint: on the l, ec, type, Esc.
  3. Line 3: delete the whole line. Hint: xd.
  4. Line 4 (now line 3): change blue to green. Try it backwards: put the cursor on the last letter of blue, then bc. b selects back to the word start, including the character you started on.

Save and quit with :wq, then:

diff /tmp/hx-lesson1.txt - <<'TXT'
the brown fox
jumps over the sleepy dog
colour = green
keep this last line
TXT

Any output is a diff between what you produced and what was expected. Fix and re-run until it's silent. If a key did something you didn't expect, u undoes it.

Where this goes next

Everything you'll learn later is this rhythm with a smarter first half: s selects every regex match inside the current selection, giving you one cursor per match, and then c changes all of them at once. That's the IDE's "select all occurrences", built from the same two-step you just practiced.
